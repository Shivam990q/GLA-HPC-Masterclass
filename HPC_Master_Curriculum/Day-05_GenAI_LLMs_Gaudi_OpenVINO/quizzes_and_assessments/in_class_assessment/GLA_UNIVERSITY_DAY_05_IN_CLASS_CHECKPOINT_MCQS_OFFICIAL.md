#### Question 01
In Large Language Model (LLM) inference on modern server processors, why is the autoregressive token generation phase ('decode phase') classified as strictly memory-bandwidth bound rather than compute-bound?

- **(a)** Because the CPU halts its arithmetic logic units (ALUs) during token emission.
- **(b)** **[CORRECT]** Because generating each new token requires streaming billions of model weight parameters and past KV-cache states from DRAM to on-chip caches for just a single batch of matrix-vector multiplications, resulting in an operational arithmetic intensity far below the machine's ridge point.
- **(c)** Because matrix multiplications cannot be performed on floating-point numbers.
- **(d)** Because the operating system requires an Ethernet handshake before each emitted token.

> **Correct Answer**: **(B)**  
> **Bloom's Cognitive Level**: `Understand`  
> **Architectural Rationale**: During the autoregressive decode phase, prompt tokens have already been processed; each subsequent token is generated by loading the entire model weights (e.g., 14 GB for a 7B FP16 model) and KV-cache tensors just to compute one vector-matrix product per layer. With arithmetic intensity ~1-2 FLOPs/byte, DRAM bandwidth saturates long before compute engines reach peak utilization.

#### Question 02
What is the primary microarchitectural purpose of Intel Advanced Matrix Extensions (AMX) introduced in 4th/5th Gen Intel Xeon Scalable processors (Sapphire Rapids / Emerald Rapids)?

- **(a)** To replace DDR5 memory controllers with optical transceivers.
- **(b)** **[CORRECT]** To provide dedicated hardware 2D register tiles (TMM0-TMM7) and a systolic Tile Matrix Multiply Unit (TMUL) capable of performing 2,048 INT8 or 1,024 BF16 operations per cycle per core.
- **(c)** To convert Python bytecode into C++ at compile time.
- **(d)** To emulate ARM NEON instructions on x86 servers.

> **Correct Answer**: **(B)**  
> **Bloom's Cognitive Level**: `Knowledge`  
> **Architectural Rationale**: Intel AMX consists of two main architectural components: eight 1KB 2D tile registers (TILECFG / TMM0-TMM7) and a systolic matrix execution unit called TMUL. TMUL performs bfloat16 (TDPBF16PS) and INT8 (TDPBUSD) dot-product matrix multiplies, delivering up to an 8x throughput leap over AVX-512 VNNI.

- **(a)** Because INT4 activations are illegal under IEEE floating-point standards.
- **(b)** **[CORRECT]** Because quantizing activations dynamically requires complex runtime calibration and can severely degrade model perplexity, whereas quantizing static weights alone cuts DRAM bandwidth consumption by ~4x with negligible loss in accuracy during memory-bound decoding.

> **Correct Answer**: **(B)**

Weight-Only INT4 quantization shrinks weight footprints from 16 bits to 4 bits per parameter, slashing memory traffic by ~75%. Activations (token representations) remain in FP16/BF16, avoiding dynamic outlier clipping and preserving generational quality.

#### Question 06
In the mathematical formulation of Low-Rank Adaptation (LoRA), given a frozen weight matrix $W_0 \in \mathbb{R}^{d \times k}$, how is the updated weight matrix $W$ parameterized during fine-tuning?

- **(a)** $W = W_0 \times (B + A)$
- **(b)** **[CORRECT]** $W = W_0 + \Delta W = W_0 + \frac{\alpha}{r} (B \cdot A)$, where $B \in \mathbb{R}^{d \times r}$, $A \in \mathbb{R}^{r \times k}$, and rank $r \ll \min(d, k)$.
- **(c)** $W = \frac{W_0}{\alpha \cdot r} + \log(B \cdot A)$
- **(d)** $W = W_0 - (A^T \cdot B^T)$

> **Correct Answer**: **(B)**  
> **Bloom's Cognitive Level**: `Apply`  
> **Architectural Rationale**: LoRA freezes the pre-trained weight matrix $W_0$ and decomposes the task-specific update $\Delta W$ into the product of two low-rank matrices: $B \in \mathbb{R}^{d \times r}$ (initialized to zeros) and $A \in \mathbb{R}^{r \times k}$ (initialized with Gaussian noise). The hyperparameter $\alpha$ scales the update, drastically reducing trainable parameters by up to 99.9%.

#### Question 10
What is the key functional difference between Continuous Batching (also known as Iteration-Level Batching) and traditional Static Batching in LLM serving engines?

- **(a)** Continuous batching requires all requests in a batch to have identical prompt lengths and generation lengths.
- **(b)** **[CORRECT]** Continuous batching dynamically inserts newly arriving requests into the active iteration loop and evicts finished requests immediately upon emitting an EOS token, eliminating padding overhead and GPU idle time.
- **(c)** Continuous batching runs only on single-core microcontrollers.
- **(d)** Static batching generates tokens 10x faster than continuous batching.

> **Correct Answer**: **(B)**  
> **Bloom's Cognitive Level**: `Analyze`  
> **Architectural Rationale**: In static batching, all requests in a batch are padded to the maximum sequence length and the entire batch must wait until the slowest request finishes before new work can be scheduled. Continuous batching operates at the token-iteration level, retiring completed sequences and admitting new requests dynamically at every single decode step.

#### Question 14
Why is PagedAttention (as implemented in modern LLM serving engines) considered an architectural breakthrough for KV-cache memory management?

- **(a)** It eliminates the need for any KV-cache in transformer models.
- **(b)** **[CORRECT]** It borrows the classic OS virtual memory paging concept to store KV-cache tensors in non-contiguous physical memory blocks, completely eliminating internal and external memory fragmentation and enabling near-zero memory waste (~4%).
- **(c)** It writes all attention matrices directly to NVMe SSDs.
- **(d)** It doubles the parameter count of the underlying neural network.

> **Correct Answer**: **(B)**  
> **Bloom's Cognitive Level**: `Understand`  
> **Architectural Rationale**: Traditional KV-cache allocation pre-allocates contiguous memory blocks for the maximum possible sequence length (e.g., 4K tokens), leading to 60-80% memory waste due to internal and external fragmentation. PagedAttention divides the KV-cache into discrete physical pages (e.g., 16 tokens/page) linked via a page table, allowing dynamic allocation.

#### Question 25
Why is INT4 weight-only quantization superior to INT8 weight-only quantization for LLM serving on memory-bandwidth-limited edge and server CPUs?

- **(a)** Because INT4 requires zero CPU power consumption.
- **(b)** **[CORRECT]** Because INT4 cuts the weight tensor size in half compared to INT8 (and 4x compared to FP16), halving the bytes that must be read across the DDR5 memory bus per emitted token and translating directly to a near-2x boost in decode throughput.

> **Correct Answer**: **(B)**  
> **Bloom's Cognitive Level**: `Evaluate`  
> **Architectural Rationale**: Since autoregressive decode is strictly memory-bandwidth bound, the generation speed is directly proportional to memory throughput divided by model size in bytes ($Tokens/sec \propto Bandwidth / ModelBytes$). Halving the model bytes from INT8 (1 byte/param) to INT4 (0.5 bytes/param) doubles the theoretical upper bound of decode speed.
